# AudCap Svelte UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the egui window and the transcriber's web page with one Svelte app shown in a wry window, and split the repo into `frontend/` and `backend/`.

**Architecture:** `audcap.exe --settings|--recordings` opens a tao window with a wry WebView. A custom protocol (`http://audcap.localhost/`) serves the embedded Svelte build plus a small JSON/file API implemented as pure, unit-tested Rust (`web_api`). The page calls the optional Python transcriber API (`http://127.0.0.1:8765`) directly for jobs and models; everything else works without it.

**Tech Stack:** Rust (wry 0.57, tao 0.37, include_dir 0.7, http 1), Svelte 5 (runes) + Vite + TypeScript + Vitest, FastAPI (existing).

**Spec:** `docs/superpowers/specs/2026-11-16-svelte-ui-design.md`

## Global Constraints

- **Never commit** (repo CLAUDE.md overrides this skill's commit steps). Leave everything uncommitted; move files with plain `mv`, not `git mv`.
- No tests for the Python transcriber (repo rule). Rust logic: tests first, `cargo test --lib`. Frontend logic: Vitest.
- Prefer debug builds while iterating; release uses LTO and lots of RAM.
- Live runs use scratch `AUDCAP_CONFIG` and `AUDCAP_TRANSCRIBER_SETTINGS`; never touch `%APPDATA%\AudCap\config.toml` or the real recordings.
- Custom protocol origin: `http://audcap.localhost`. Transcriber base URL: constant `http://127.0.0.1:8765`.
- CSP: `default-src 'self'; connect-src 'self' http://127.0.0.1:8765; media-src 'self'; style-src 'self' 'unsafe-inline'`. No remote fonts or scripts.
- WebView2 user data folder: `%LOCALAPPDATA%\AudCap\webview`.
- The tray process never loads WebView2 (window stays a separate process; mutex `Local\AudCap.Settings`).
- Window: resizable, default 1100×720, min 760×520, title "AudCap".
- Recording id = path relative to `output_dir` with `/` separators (same as the transcriber's ids).

## Review Focus

- **Seeking a long recording:** the `<audio>` element sends `Range: bytes=N-`; the API must answer 206 with a correct `Content-Range`, and a bad range must give 416, not a panic. (Task 2 tests.)
- **Hostile or odd ids:** `../`, absolute paths, backslashes, a `.json` id, a missing file → 404, never a file outside `output_dir`. (Task 2 tests.)
- **Transcriber goes down mid-session:** polling must flip to offline quietly and recover when it comes back; transcripts on disk still open. (Task 7 test on `pollState` reducer.)
- **Hand-edited or odd transcripts:** unknown lines ignored, `_No speech detected._`, hours ≥ 10, missing title — parser never throws. (Task 6 tests.)
- **Saving an invalid form value** (bitrate 999, grace 0, empty custom apps) saves the sanitized value and the form shows what was saved. (Task 3 test on PUT round-trip.)

### Task 3: web_api router

**Files:**
- Modify: `backend/recorder/src/web_api/mod.rs`

**Interfaces:**
- Consumes: Task 2; `config::{Config, KNOWN_APPS}`; `audio::device::DeviceInfo` (add `#[derive(Serialize, Clone)]`).
- Produces:
  - `pub trait Host { fn config_path(&self) -> PathBuf; fn devices(&self) -> (Vec<DeviceInfo>, Vec<DeviceInfo>); fn pick_folder(&self, start: &Path) -> Option<PathBuf>; fn open_folder(&self, dir: &Path); }`
  - `pub fn handle(host: &dyn Host, req: &http::Request<Vec<u8>>) -> http::Response<Vec<u8>>` — routes below; anything not `/api/*` goes to `assets::serve(path)` (Task 4; until then return 404).
  - Routes (JSON = `application/json`; errors are `{"error": "…"}`):
    - `GET /api/config` → `{"config": Config, "known_apps": [..]}` (`Config::load_or_create`).
    - `PUT /api/config` → body is `Config` JSON → `.sanitized()` → `save` → 200 same shape as GET; 400 on bad JSON; 500 on write error.
    - `GET /api/devices` → `{"mics": [...], "speakers": [...]}`.
    - `GET /api/recordings` → `{"output_dir": "...", "recordings": [RecordingJson]}`.
    - `GET /api/transcript?id=` → `.md` as `text/markdown; charset=utf-8`; 404 when the id doesn't resolve or there's no `.md`.
    - `GET /api/audio?id=` → `audio/ogg`, `Accept-Ranges: bytes`; no `Range` → 200 whole file; `Range` → 206 + `Content-Range: bytes s-e/len` (open-ended capped at `MAX_CHUNK`); bad range → 416 + `Content-Range: bytes */len`.
    - `POST /api/open-folder` body `{"id": string|null}` → opens the recording's folder (or `output_dir`) → `{}`.
    - `POST /api/pick-folder` → `{"path": string|null}` (starts at current `output_dir`).
    - Unknown `/api/*` → 404; wrong method → 405.
  - Query parsing: percent-decode `id` (ids contain spaces? no, but `/` arrives encoded as `%2F`). Use `url::form_urlencoded` (add `url = "2"`) or a small decoder.
